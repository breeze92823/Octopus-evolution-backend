# Octopus Evolution — BACKEND (game server)

Frontend (3D client) lives at `../Octopus-evolution` (client side of this contract: `src/net.js`, `src/state.js`). Colyseus + Mongo, ported from the Bowling Roll server.

- `npm start` (tsx watch, port 2567), `npm run build` (tsc -> `build/`), `npm test` (mocha + `@colyseus/testing`, Mongo faked via `__setPlayersForTest`; tests share one booted server, `test/server.ts`). Node >= 22.
- One room, `world` (`src/rooms/WorldRoom.ts`, client calls `joinOrCreate("world", { token, username, pfp, loadout, avatar })`). Client-authoritative: the server only bounds/sanitises saves (`src/sanitize.ts`). `src/db.ts` degrades to "no persistence" when `MONGODB_URI` is unset/unreachable; guests (no / refused token) are never saved. `/health` for Legion; `/monitor` and the playground are dev-only.
- The server's Mongo doc is the signed-in player's real save. The client also keeps a localStorage copy (`state.js`) as the offline / guest fallback and the first paint; when the server answers `progress` it replaces that. A guest's (or a serverless session's) progress lasts that browser only.
- Messages client -> server: `saveProgress` (the whole snapshot, debounced client-side), `identify` (`{ token, devId?, username, pfp }` after a sign-in/out mid-session; the token is verified again), presence: `loadout` `{ tentacle, level, title, trail, ascend }`, `setAvatar` `{ avatar }`, `pose` `{ x, y, z, yaw, speed }`, `emote` `{ id }` (`""` = stopped). Server -> client (private): `progress` (the saved doc, sanitized, + `serverTime`), `noProgress` (new account, guest, or no database: the client keeps its state and, if signed in, saves it as the first save), `serverError` (the save could not be read: saving stays off so it is never overwritten), `leaderboard`. Saves are ignored until the session's load has answered (`loaded`). A second live session on the same account is evicted.
- Saved progress shape (`PlayerDoc`): exactly the client's `state` object (`src/state.js` `fresh()`, `SAVED_KEYS`): `wins` (balance), `totalWins` (earned ever), `level`, `xp`, `rebirths`, `owned[]`/`equipped` (tentacle skin ids; the equipped id must be owned, never ""), `zonesBought[]` (Wins-priced training zone ids), `bestStage` (lane stage cleared), `playtime` (s), `train2x` (s left on the x2 Train potion), `wins2x`, `starter`, `bossTimer` (s until the hub boss), meta progression `items` { train, wins, damage, speed } (boosts held), `wins2xT`/`dmg2xT`/`speedT` (s left on used boosts), `titles[]`/`title` ("" = none, must be earned), `titlesSeen[]`, `trails[]`/`trail` ("" = none, must be owned), `ascend` (tier), `stats` { counter: n } (title progress, at most `STATS_KEYS_MAX` id keys), plus server-side `lastSeen`, `username`. `totalWins`, `bestStage` and `playtime` are written with `$max` so a stale tab can never lower them. Bounds are in `src/constants.ts` (`CURRENCY_MAX`, `LEVEL_MAX`, `STAGE_MAX`, ...); catalog ids match `ID_PATTERN`.
- Leaderboards (`src/leaderboard.ts`, `test/Leaderboard.test.ts`): the client hub's four boards. Top `LEADERBOARD_SIZE` saved players by each of `LEADERBOARD_STATS` (`totalWins` = Most Wins, `rebirths`, `playtime`, `bestStage`; the same names as the state keys), read with find/sort/limit into one process-wide cache refreshed at most every `LEADERBOARD_EVERY_MS`; each player's own rank = countDocuments(stat > theirs) + 1 (null for guests / no score). Server -> client `leaderboard` { boards: { stat: [{ name, value }] }, ranks: { stat: n | null } }, sent after each load and to everyone every `LEADERBOARD_EVERY_MS` (room clock). `connectDb` creates a descending index per stat. The test fake supports just that find/countDocuments shape. The client draws `boards` on the hub pillars (`main.js` `refreshBoards`); `ranks` is sent but not shown yet.
- Identity (`src/auth.ts`, `test/Bloxity.test.ts`): Bloxity rule, enforced for every game server. The account id is ONLY what the platform returns when the server verifies the client's `token` (`Legion.SDK.auth.getToken()`) with `POST {BLOXITY_API_URL}/v1/auth/game-token/verify { gameSlug }` in `onAuth` / `identify`. A missing, refused or unverifiable token is a guest (nothing loaded or saved); a client-sent `userId` / `profileId` is ignored. Local dev (vite dev server, no Bloxity sign-in) joins with `devId: "dev-xxxx"`, honoured only when `NODE_ENV !== "production"`.
- Presence (`src/presence.ts`, `test/Presence.test.ts`, `test/Bloxity.test.ts`): what the others draw in the world, relayed through the roster, only bounded. Roster (`PlayerState`): `username`, `signedIn`, `uid` (verified Bloxity id: matches Bloxity chat's `userId` for overhead bubbles), `pfp` (http(s) only, max `PFP_MAX_LEN`), `x`/`y`/`z` (feet, hub coordinates), `yaw` (wrapped to -PI..PI), `speed`, `tentacle`, `level`, `avatar` (the Bloxity look: `sanitizeLook` keeps only the 20 equipped-slot ids, the 7 proportions clamped to the SDK ranges and the outfit key, as JSON; never URLs, so no client can point another at an arbitrary URL), `emote` + `emoteSeq` (opaque Bloxity emote id and a start counter). The client draws the nearest players as octopi wearing their look (`src/remotePlayers.js`).
- Bloxity platform integration (docs.bloxity.io, hosting.bloxity.io/docs): (1) **Open Rooms**: `src/legion-room-reporter.ts` (`installRoomReporter()` in `index.ts`) pushes this pod's public rooms to the matchmaker every 2 s (needs hosting's `BLOXITY_REPORT_TOKEN`, `MATCHMAKER_REPORT_URL`, `BLOXITY_GAME_ID`; a no-op elsewhere), which fills the game page's list and the Join button (`?roomId=`); the client resolves the room's pod and joins it (`net.js` `joinLaunchRoom`) and reports its room with `updateRoom()` for friend invites. (2) **Leaderboards + stats**: `src/boxity.ts` reports from the saved progress (never a client message) to `POST /v1/leaderboards/hosted/{id}/report` (boards `wins`, `rebirths`, `stage`, `playtime` in minutes: `BOXITY_BOARDS`, declared by the first call and by the client's `leaderboard.define`) and `POST /v1/games/{id}/stats` (`BOXITY_STATS`), batched every `BOXITY_FLUSH_MS`, only changed values, `legion_<id>` identities only (dev ids skipped), stats above the platform ceilings left out, flushed on room dispose. Changing a board id in `constants.ts` also means `config.js` `BLOXITY_BOARDS` / `BOARD_LINKS`. (3) Party play and "Play with friends" need nothing more: hosted on Legion + matchmaker + `ROOM_MAX_CLIENTS` 2-100. Deploys never send `seatCap`, only `roomSize`.
- Daily Rewards (`src/daily.ts`) + Playtime Rewards (`src/gifts.ts`), `test/Rewards.test.ts`: server-authoritative, unlike the rest of the save. Doc fields `dailyDay`/`dailyLast` (UTC day index)/`dailyClaimed[]`/`dailyStreak` and `giftTime` (s played this round)/`giftClaimed[]` are written only by the room, never by `saveProgress` (not in sanitize.ts). Daily: one more day (of `DAILY_DAYS`) unlocks per consecutive UTC day, a missed day resets the calendar and streak, a fully claimed week starts over (streak keeps counting); rolled on load and stored at once. Gifts: gift i opens at `GIFT_MINUTES[i]` min of play counted on the server clock while connected (kept on leave via `stampLastSeen`), 2 s slack, the last claim restarts the round. After the load the server sends `daily` { unlocked, claimed, streak, nextAt, serverTime, persisted } and `gifts` { time, claimed, serverTime, persisted }; client -> `claimDaily` { day } -> `dailyResult` { ok, day, reason?: loading | locked | save, ...view }, `dailyRefresh` -> `daily`, `claimGift` { gift } -> `giftResult` { ok, gift, reason?: loading | bad | early | save, ...view }; ok only once stored, the client grants the reward then. `persisted: false` (guest / no database) = the client runs its local copy instead.
- `src/constants.ts` bounds must cover the client's `src/config.js`. A contract change goes in both projects (this file, `sanitize.ts` + `db.ts` here; `state.js` `fresh()` and `net.js` there).
- CI/CD: `.github/workflows/deploy.yml` tests on PRs and pushes to `main`/`dev`; pushes also build+push a GHCR image and deploy to Bloxity Legion (`main` = prod, `dev` = dev), sending `roomSize` = `ROOM_MAX_CLIENTS` read from `src/constants.ts` (keep it 2-100 for party play; no `seatCap`: the matchmaker sizes pods). Needs repo var/secret `LEGION_GAME_ID` (= `octopus-evolution`) and secret `LEGION_DEPLOY_TOKEN`.
